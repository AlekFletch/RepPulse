Обновлено: 2026-09-24. Этап 3 по ТЗ: UI-навигация и основные экраны, локальное хранилище, `WorkoutSessionController`, countdown и rest timer, абстракция вибрации. Автоподсчёт повторов — Этап 4.

> **После Этапа 4 изменилось** ([docs/07 §4](07-stage4.md)): отдых вынесен на отдельную страницу `rest`, сессия между страницами лежит в `workouts/last.json`; итоги считает страница `summary`; план создаётся на страницах запуска; состояния страницы тренировки переключаются через `if`; на `workout` подключены датчики и движок подсчёта, а касание по счётчику в debug-сборке по-прежнему засчитывает повтор. **На Этапе 5** ([docs/08 §1](08-stage5.md)) `SettingsRepository` перешёл со `storage` на файл `settings.json`. Ниже — описание на момент Этапа 3.

## 1. Экраны и переходы

На lite есть только `router.replace`, стека страниц нет. Каждая страница — отдельный бандл, общей памяти JS между страницами нет. Данные передаются в параметрах перехода и через хранилище. «Назад» — кнопка «‹» в шапке или свайп вправо.

| Страница | Что на ней | Куда ведёт |
|---|---|---|
| `index` | иконка RepPulse, «Тренировка», плитки «Приседания», «Отжимания», «История», кнопка «Настройки»; в debug — «Диагностика» | `exercise`, `history`, `settings` |
| `exercise` | иконка и название упражнения, подсказки из ТЗ, предупреждение о низком заряде; «Свободный режим», «На время», «Подходы», «Калибровка» | `workout` (свободный), `timerSetup`, `setsSetup`, `calibration` |
| `timerSetup` | длительность 10 с – 60 мин (шаг 10 с / 30 с / 1 мин), вибрация на повтор | `workout` |
| `setsSetup` | подходы 1–20, цель повторов (можно выключить), время работы (можно выключить), отдых 10 с – 10 мин, автостарт, вибрация на повтор; ошибка «Задайте цель…» | `workout` |
| `workout` | состояния на одной странице: отсчёт 3-2-1, активный подход, пауза (+1 / −1 / Продолжить / Завершить), отдых (Начать сейчас / +15 сек / Завершить тренировку) | `summary` |
| `summary` | «Тренировка завершена», показатели §4.1 ТЗ, результат каждого подхода; «Сохранить», «Повторить», «На главную» | `workout`, `index` |
| `history` | список тренировок: дата, время, длительность, упражнение, повторы, подходы; «Удалить всю историю» с подтверждением | `historyDetail` |
| `historyDetail` | общая статистика, разбивка по подходам с ручными корректировками; удаление записи с подтверждением | `history` |
| `settings` | рука, вибрация, вибрация на повтор, отсчёт 3-2-1, чувствительность; «RepPulse, Версия 1.0.0» | `index` |
| `calibration` | выбор руки и инструкция. Сама калибровка — Этап 4 | `exercise` |

## 2. Логика (`common/`)

- **`workout/WorkoutSessionController`** — тренировка целиком: подходы, пауза, отдых, цели по повторам и по времени (что наступит раньше), учёт активного времени и времени отдыха, ручная корректировка (итог подхода не уходит ниже 0), автопауза в `onHide`. Страница только вызывает методы и рисует `snapshot()`. 14 тестов на фейковых часах.
- **`CountdownController`**, **`RestTimerController`** (конец отдыха считается от абсолютного времени, короткие вибрации за 3-2-1 секунды, «+15 сек»), **`HapticFeedbackController`** (сигналы §1.5 ТЗ; «сильная» вибрация = long + long).
- **`detection/RepDetector`** — контракт детектора. До Этапа 4 стоит пустой детектор, повторы исправляются вручную на паузе. В debug-сборке касание по счётчику имитирует повтор, чтобы можно было проверить подходы.
- **Хранилище:**
  - `WorkoutRepository` — `workouts/index.json` (сводки, новые сверху, не больше 100) и `workouts/w_<id>.json`;
  - `LastSessionStore` — `workouts/last.json`: только что законченная тренировка для экрана итогов;
  - `SettingsRepository` — по ключу на поле, потому что значение в `storage` не длиннее 128 символов;
  - `CalibrationRepository` — файл на упражнение и руку;
  - `storage.get/set` при сбое повторяются один раз.
- **UI-модели:** `ui/setupSteps` (шаги «−/+», «Выкл.», проверка плана), `ui/summaryView` (строки итогов), `ui/launch` (параметры для `workout`), `ui/page` (переходы, фокус колёсика, `setIfChanged`).

Тесты: 133 (`npm test`), lint (`npm run lint`).

## 3. Особенности lite, найденные на этом этапе

| Проблема | Что происходит | Решение |
|---|---|---|
| **Страница > 48 КБ не открывается** | `FILE_CONTENT_LENGTH_MAX` в ArkUI ACE lite; в симуляторе — предупреждение `is bigger than 48 KB` и `JS HEAP OOM` | SDK минифицирует JS только в release (`hapMode = !debug`), а release-пакет DevEco Assistant не ставит (*Failed to decompress*). Поэтому задача `RepPulseMinifyLiteJS` в `entry/hvigorfile.ts` минифицирует JS в обычной debug-сборке (`tools/minify-lite.js`, terser из SDK). Страница тренировки: 58 → 32 КБ. `npm run check:bundles` проверяет размеры |
| **Куча JS ~100 КБ** | Байткод страницы, строки и объекты делят одну кучу; сценарий из двух подходов не проходит при 80 КБ | Страница тренировки не читает хранилище (настройки приходят в параметрах), датчики на Этапе 3 не подключены, `toAsciiJson` не собирает строку посимвольно |
| **`render` и `styleSheet` — зарезервированные имена** | Загрузчик кладёт в `render` скомпилированный шаблон и молча затирает метод страницы → `TypeError: Expected a function` | Методы названы `paint`; ESLint запрещает эти имена в объекте страницы |
| **`$t` без параметров вырезает `{плейсхолдеры}`** | `$t('strings.cadence')` → « повт./мин» | Шаблоны только через `$t(ключ, параметры)` |
| **`show=false` у `list-item` оставляет пустое место** | Кнопки уезжают вниз, касания промахиваются | В списках — `if`, у полноэкранных `div` — `show` |
| **Пакет вдвое тяжелее обычного** (978 КБ) застрял на *Transferring* в DevEco Assistant | В `.bin` попадали карты исходников `.js.map` (~390 КБ); каждая картинка едет дважды (PNG + `.bin`) | Задача минификации удаляет `.js.map`; из иконок экспортируются только используемые размеры (28 и 64 px, иконка приложения 48 px). Пакет — 448 КБ, как прошлые установленные |
| Привязка данных в `class` не компилируется (урок BreathTrainer) | — | Цвета выбора — через `style` |
| Фокус колёсика у удалённого списка роняет движок (урок BreathTrainer) | — | Уход со страницы только через `go()`, который снимает фокус |

## 3.1. Исправлено после первой проверки на часах (2026-09-24)

- **«Свободный режим» не запускался.** Страница ждала загрузку настроек из `storage` в момент нажатия, а колбэк на часах не приходил. Теперь настройки грузятся при открытии экрана, старт не ждёт хранилище. Кроме того, `storage.get/set` в `LocalStorageAdapter` сами завершаются через 1,5 с, если часы не ответили (`KV_TIMEOUT_MS`).
- **Подсказки на экране «Отжимания» наезжали на кнопки.** Размер блока `text` на lite не растёт вместе с текстом, а на часах русский текст переносится по словам и занимает больше строк. Высота блоков теперь с запасом.
- **Свайп слева направо:**
  - на главном экране закрывает приложение;
  - в тренировке ставит паузу и спрашивает «Завершить тренировку?»: «Да» открывает итоги, «Нет» продолжает;
  - в итогах ведёт на главный экран;
  - на остальных экранах — «назад».
- **В итогах обрезались значения** («Свободный ре…»). Колонки подписей и значений перераспределены.
- «На время» и «Подходы» не реагируют на движения — так и задумано на Этапе 3: движок подсчёта появится на Этапе 4.

## 4. Симулятор без DevEco Studio

`tools/simulator.py` запускает `Simulator.exe` из SDK (408×480), проигрывает сценарий и сохраняет скриншоты:

```bash
python tools/simulator.py --url pages/index/index --out shots "wait 2" "shot home" "tap 200 145" "wait 1.5" "shot exercise"
```

Шаги: `wait <сек>`, `tap <x> <y>`, `swipe <x1> <y1> <x2> <y2>` (медленный, как палец), `crown <n>`, `shot <имя>`. В лог выводятся ошибки движка и `console.info`; при `JS HEAP OOM` печатается раскладка памяти. `--heap` задаёт размер кучи (по умолчанию 102400). `--lang` (по умолчанию `ru-RU`): собственный флаг `-l` lite-симулятор игнорирует, поэтому скрипт подкладывает `ru-RU.json` на место `en-US.json` в копии бандла. Учтите: симулятор переносит строки по буквам, а часы — по словам, поэтому на часах текст занимает больше строк.

В симуляторе нет датчиков (`@system.sensor` бросает исключение), и колёсико не прокручивает список. Это нужно проверять на часах.

Проверено в симуляторе: свободный режим (отсчёт → счёт → пауза ±1 → итоги), подходы (2 подхода, отдых 10 с с вибрациями 3-2-1, автостарт, итоги 6 повторов / 2 подхода / отдых 00:10), сохранение → история → запись → удаление, настройки.

## 5. Что проверить на часах

1. Установка пакета.
2. Прокрутка списков колёсиком и касанием, свайп вправо «назад».
3. Свободный режим, «На время», «Подходы»: отсчёт, вибрации, отдых, автостарт, итоги.
4. Сохранение и история после перезапуска приложения.
5. Экран не гаснет во время тренировки. Что происходит при нажатии кнопки и при уведомлении: ожидается автопауза.
